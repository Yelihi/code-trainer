# P11 일반 자료의 복습 일정

기존 코드 복습은 유지한다. 해석, 저장한 답변·요약, 직접 쓴 노트에서 별도 ‘복습에 추가’를 누르면 정확한 종류/ID/버전의 일정을 만든다. 추출 적격 확인이나 그래프 등록이 선행 조건은 아니다. AI 키 없이 가능하며 같은 버전 중복 추가는 같은 일정을 반환한다. 노트/작성분의 미저장 편집 상태에서는 추가를 막는다.

일정은 추가 당시 제목·본문·작성 주체와 원본 버전을 보존한다. 원문/작성분 변경·보관 상태를 매 조회/완료 시 확인한다. 오래된 대상은 본문과 기록은 유지하되 완료를 막고 원래 화면에서 최신 버전을 별도 등록하도록 안내한다. 기존 노트 AI 대화 복습은 그대로 별도 유지한다.

처음은 추가 시점+1일(UTC instant). 예정 시각 이후 ‘스스로 설명 가능’이면 연속3·7·14일 간격(이후14일), ‘다시 확인 필요’이면 연속값0으로 초기화하고 다음 날이다. 단순 열람은 완료가 아니다. 응답에는 일정 revision과 request ID를 보내고 한 트랜잭션에서 응답/기한/revision을 저장한다. 동일 요청 재전송은 저장한 결과, 변경된 payload/오래된 revision은409. 다른 owner, 미래 기한, 변경·보관된 자료는 완료할 수 없다. 자기평가를 코드 채점이나 숙달 점수로 기록하지 않는다.

다시 검토 화면에서 코드와 일반 자료의 예정 기한을 함께 보여준다. 오늘부터7일의 날짜별 건수와 기한 경과 항목을 시각화한다. 날짜 그룹은 브라우저 현지 날짜로 표시하고 예정/완료 가능은 서버 UTC 시각 기준이다. 자료의 고정된 본문을 읽고 명시적으로 자기평가를 제출하는 상세 화면을 추가한다. 실패 시 입력/기록을 보존하며 POST 자동 재시도는 없다.

검증: 종류별 명시 등록/추출 독립/owner, UTC 기한 직전과 정각,1·3·7·14/실패 초기화,동시 중복/변경 payload/낡은 revision,원문/답변 변경과 노트 보관,고정 본문 보존. 기존 코드 도움 이력 및 노트 회귀. 날짜 그룹 단위검증과 실제 브라우저 등록→목록/주간일정→본문열람(변경 없음)→자기평가→다음기한,미래/오래된 상태,390px. Release만 병합.
