# 실패한 해석의 동일 항목 재시도와 보존형 삭제

## 당시 요청과 제약

사용자는 실패한 해석의 **재시도**가 새 해석본을 만드는 대신 해당 자료에서 이뤄져야 하며, 해석 자료를 삭제할 수 있어야 한다고 요청했다. 이는 [발화 발췌](../raw/ct-20261111-001-request.md)에 남겼다. 전체 대화와 임시 스크린샷은 확인 가능한 원본으로 보존하지 못했다.

## 구현에서 확인한 선택

[PR #54](https://github.com/Yelihi/code-trainer/pull/54)는 실패·중단 상태의 해석을 **같은 ID와 원문 버전**에서 재시도하도록 변경했다. `attempt` 번호로 늦게 도착한 이전 실행 결과가 새 시도를 덮어쓰지 못하게 했다. 완료된 해석에서 새 버전을 만드는 흐름은 별도로 남았다. [병합 시점의 구현](https://github.com/Yelihi/code-trainer/blob/8d1ed412b6fadd3483f1e9052e5e05ceef236140/backend/interpretations.py)을 기준으로 한 관찰이다.

같은 PR은 삭제를 `archived` 표시와 목록 분리·복원으로 구현했다. 질문지와 복습 기록이 해석을 참조하므로 원본 행을 물리적으로 지우지 않는 선택이었다. **이 보존 방식이 사용자에게 명시적으로 확인된 것은 아니다.** 연결 기록 손상을 피하려는 구현 판단으로 구분한다.

## 확인된 결과와 남은 확인

PR 설명에는 해석·자료 검토·질문지 백엔드 테스트 23개와 프론트엔드 빌드·타입 검사·린트 통과가 기록돼 있다. [병합 커밋](https://github.com/Yelihi/code-trainer/commit/8d1ed412b6fadd3483f1e9052e5e05ceef236140)은 2026-11-05에 생성됐다. 이 근거는 코드 반영과 자동 검증을 보여주며, 실제 사용자가 재시도·복원 화면을 조작한 결과까지 증명하지는 않는다.

물리 삭제가 필요해지거나 연결된 질문지·복습 기록의 보존 정책이 바뀌면 삭제 정책을 다시 검토해야 한다. 이 기록의 `current`는 이후 대체 기록이 없다는 뜻이며, 지금도 최선의 설계라는 보증이 아니다.
