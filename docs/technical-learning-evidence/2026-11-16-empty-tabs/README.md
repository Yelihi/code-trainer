# 빈 상태와 복습 탭 보완 — 2026-11-16

사용자 피드백에 따라 복습 화면의 세로 나열을 자료·내 문제·코드·일정 탭으로 나눴다. URL의 tab으로 선택을 보존하며, 긴 주기 설명은 펼침 안내로 이동했다. 자료·노트·질문·문제·자동 수집의 빈 목록은 공통 EmptyState를 사용한다. 최소 높이는 220px, 모바일 200px이며 56px 아이콘과 제목·설명·필요한 행동을 중앙에 표시한다. 그라데이션은 이어서 하기 카드와 빈 상태 아이콘 배경에만 사용한다.

## 캡처 출처

실제 production build를 Chrome에서 열고 DevTools 반응형 뷰포트의 스크린샷 캡처로 저장했다. 브라우저 UI가 포함되지 않은 첫 뷰포트 PNG이며 이미지 생성·합성·후처리는 없다. 격리된 임시 DB의 합성 예시를 사용해 사용자 개인 자료를 포함하지 않는다.

- reviews-desktop.png (코드 탭), today-desktop.png: 1440×1000 CSS, 2880×2000 PNG.
- reviews-mobile.png (자료 탭), problems-mobile.png, code-mobile.png, schedule-mobile.png, today-mobile.png: 390×844 CSS, 780×1688 PNG.
- 모든 이미지 DPR 2. 처음 세 모바일 복습 캡처는 활성 탭 hover 우선순위 보정 직전이며 구성·내용·높이는 같다. 최종 일정과 Today 캡처는 보정 후다.

## 검증과 한계

실제 클릭으로 자료→내 문제를 전환했고 Right 방향키로 코드 탭을 선택했을 때 URL과 활성 패널이 함께 바뀌는 것을 확인했다. 일정의 빈 상태도 확인했다. SSR 검사는 네 URL 탭의 선택·단일 표시, 잘못된 tab의 기본값, 로딩을 빈 데이터로 오인하지 않는 계약을 확인한다. 기존 질문 로딩·트리·초안 관련 검사를 포함한 frontend 32개 테스트, TypeScript를 포함한 Vite build와 ESLint가 통과했다. 디자인 detector는 주요 변경 파일에 한 번 실행해 `[]`였다.

이번 작업은 화면 구성과 공통 상태의 보완이며 백엔드·사용자 데이터·복습 주기·실행 경계는 변경하지 않았다. 이 빈 데이터 캡처는 실제 제출/복습 응답이나 유료 AI, 실기기 키보드 검증의 증거가 아니다. 기존 큰 JS chunk 경고는 유지한다. 운영에는 배포하지 않았다.

독립 검토에서 일곱 캡처와 지정 소스의 화면 구성이 요구에 맞음을 확인하고 DESIGN.md 갱신만 요청했다. 실제 컴포넌트/높이/그라데이션/탭/Chrome 검증 범위를 문서와 sidecar에 반영한 뒤, 같은 검토자의 문서 수정 판정 `ship`을 받았다. 판정은 해당 수정 범위이며 제품 전체 승인을 의미하지 않는다. [검토 기록](REVIEW.md).
