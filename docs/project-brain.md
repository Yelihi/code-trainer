# 세컨드 브레인 · LLM Wiki

사용자가 **선택하고 수정·보완한 문서**를 근거로 AI가 위키를 누적 갱신합니다. 카파시의 [LLM Wiki](https://gist.github.com/karpathy/442a6bf555914893e9891c11519de94f)의 원자료·위키·운영 규칙과 ingest / query / lint 흐름을 앱 안에 구현합니다.

## 처음 사용하는 순서

1. **데이터 쌓기 → 세컨드 브레인 → 문서 → 문서 작성하기**로 들어갑니다.
2. 직접 글을 쓰거나, **자료 보관함·원자료·PR에서 불러오기**를 엽니다. 사용할 자료를 선택하면 그 시점의 본문을 원자료 스냅샷으로 보존하고 편집기에 복사합니다. 보관 자료는 검색과 페이지 이동으로 고릅니다. GitHub PR은 설정에서 연결한 계정으로 제목과 본문을 가져옵니다.
3. 불필요한 부분을 덜고, 내가 이해한 내용·맥락·추가 설명을 보완한 뒤 **문서 저장**을 누릅니다. 원자료는 바뀌지 않습니다. 직접 쓴 문서도 사용할 수 있습니다. 이미지의 중요한 정보는 글로 설명해주세요. AI는 텍스트를 읽습니다.
4. 문서 목록에서 반영할 문서를 최대 10개 선택하고 **위키 변경안 만들기**를 누릅니다. AI는 선택한 문서 버전과 기존 위키를 함께 읽습니다. 관련 페이지를 갱신하고, 필요한 주제 페이지와 연결을 제안합니다. 이 단계에서는 위키가 바뀌지 않습니다.
5. 변경안에서 **반영 전 페이지 보기**, 새 전체 본문, 문서 인용과 연결을 확인합니다. 제목·요약·본문을 수정할 수 있습니다. **페이지에 반영하기**를 누르면 변경안 전체를 한 번에 반영합니다.
6. **위키**에서 주제별 페이지를 읽거나 질문합니다. 답변에는 사용한 위키 페이지와 버전·인용이 표시됩니다. 위키에 근거가 없으면 자료가 부족하다고 답합니다.
7. 유용한 답변은 **답변을 문서로 보완하기**로 가져와 직접 고치고 저장한 뒤 다시 반영합니다. 탐구 결과도 위키의 다음 근거로 쌓입니다.

예를 들어 배포 문서를 반영해 `배포 구조` 페이지가 생긴 뒤 SSD 장애 대응 문서를 추가하면, AI는 기존 배포 설명을 읽고 관련 페이지를 수정하거나 `외장 SSD` 페이지를 연결합니다. 자료마다 새 기록만 추가하는 방식과 다릅니다. AI의 주제 선택과 종합 결과는 반영 전에 확인해주세요.

## 무엇을 저장하는가

- **원자료**: 보관 자료의 특정 버전, GitHub PR, 기존 발췌의 변경하지 않는 스냅샷입니다.
- **문서**: 사용자가 원자료를 선택·편집·보완해 확정한 근거입니다. 저장할 때마다 버전이 남습니다. 문서 저장만으로 AI 호출이나 위키 반영이 일어나지 않습니다.
- **위키**: AI가 문서를 종합한 주제별 페이지입니다. 문서 버전의 실제 문구를 인용하고 관련 페이지를 연결합니다. 반영할 때마다 페이지 버전이 남습니다.
- **활동**: 문서 반영·질문·점검의 입력, 결과, 실패·중단·반영 상태입니다. 생성 중 화면을 나가도 활동에서 다시 열 수 있습니다.
- **운영 규칙**: 원자료를 보존하고, 기존 페이지를 먼저 읽고, 근거와 연결을 유지하고, 모르는 내용과 충돌을 드러내도록 하는 위키 관리 규칙입니다.

개인 위키는 현재 로그인한 사용자별로 분리됩니다. 특정 Code Trainer 개발 프로젝트의 결정 기록에 한정하지 않고, 사용자가 선택한 주제를 담습니다. 기존 학습 개념 그래프는 별도 기능입니다.

## 다시 보완하기

- 문서를 수정하면 기존 위키는 자동으로 바뀌지 않습니다. 문서 목록의 재반영 안내 또는 **활동 → 보완할 부분**에서 확인하고 최신 문서를 선택해 새 변경안을 생성합니다.
- **위키 점검하기**는 AI가 페이지 간 충돌·지식 공백·연결 부족 등을 검토하게 합니다. 오래된 문서 버전 인용, 끊긴 연결, 고립된 페이지는 코드로도 점검합니다. 점검이 위키를 자동 수정하지는 않습니다.
- 변경안을 검토하는 동안 문서나 위키가 바뀌면 반영을 거부합니다. 최신 내용으로 변경안을 다시 생성해주세요.
- 페이지와 근거 문서에서 이전 버전을 읽을 수 있습니다. 과거 답변은 당시의 위키 버전에 연결됩니다.
- AI 생성 실패나 서버 재시작은 저장한 문서와 기존 위키를 지우지 않습니다. 활동에서 오류를 확인하고 새 요청으로 다시 시도합니다. 응답을 못 받은 동일 요청의 중복 실행은 방지합니다.

## 기존 프로젝트 기록

**기존 프로젝트 기록**에서 예전 관찰·결정·교훈과 연결 그래프를 그대로 볼 수 있습니다. 기록 상세의 **위키 문서로 보완하기**를 누르면 기존 본문과 근거를 새 문서로 가져옵니다. 사용자가 저장하고 반영하기 전에는 새 위키에 자동 편입하지 않습니다.

## 내보내기와 현재 범위

**Markdown 내보내기**는 다음 파일을 담은 ZIP을 내려줍니다.

- `raw/`: 보존한 원자료 스냅샷
- `documents/`: 사용자가 저장한 문서의 모든 버전
- `wiki/`: 현재 위키 페이지와 문서 인용·상호 연결
- `index.md`: 위키 목차
- `log.md`: 반영·질문·점검 이력
- `AGENTS.md`: 위키 관리 규칙

앱의 원본 저장소는 SQLite이며 Markdown은 내보내기 형식입니다. 로컬 폴더·Obsidian과 실시간 동기화하거나 외부 에이전트가 파일을 자동 갱신하는 기능은 포함하지 않습니다.

첫 버전은 기존 위키 전체를 읽습니다. 선택한 문서·기존 페이지·근거 문서가 합쳐서 24만 자를 넘으면 일부를 몰래 제외하지 않고 요청을 거부합니다. 한 번의 변경안은 최대 12개 페이지입니다. 더 큰 위키에는 별도의 검색 기반 읽기 확장이 필요합니다. 페이지 간 반박의 의미와 문서의 사실성은 인용 검증만으로 보장하지 못하므로 사용자가 확인합니다.
