# 학습 기반 레퍼런스와 Skill 패키지 관리

2026-11-18 사용자 요구사항. 이 문서는 구현 기준과 로컬 검증 기록이다. feat/reference-skill-lifecycle에 구현했으며 현재 운영 배포 완료를 뜻하지 않는다. 기존 레퍼런스 기록과 생성 이력은 보존한다.

## 레퍼런스의 역할

레퍼런스는 Code Trainer에서 학습한 내용을 AI가 실제 작업에 재사용할 수 있도록 만드는 Skill 패키지다. 사람이 설명을 먼저 작성하고 별도로 Skill을 만드는 흐름을 필수로 두지 않는다. 사용자는 학습 기록 목록에서 근거를 직접 선택하거나 추천을 받아 생성 작업을 요청한다. AI는 선택한 근거의 버전을 고정한 job으로 생성하고, 결과는 사람이 읽고 수정하고 승인할 수 있다.

패키지는 SKILL.md, references/의 참고 문서, 작업에 필요한 scripts/를 지원한다. 스크립트는 생성된 코드이며 생성 완료나 사용자 승인만으로 실행 검증 완료를 표시하지 않는다. 생성이나 열람으로 스크립트를 자동 실행하지 않는다. 불필요한 스크립트를 형식상 채워 넣지 않는다.

## 사용 흐름

1. 레퍼런스 영역에서 학습 기록을 탐색한다. 선택된 기록의 내용·버전·학습/실행 근거를 확인한다.
2. 추천된 근거를 검토하거나 직접 여러 기록을 선택한다. 추천과 실제 생성 요청을 구분하며, 단순 화면 조회로 유료 생성을 시작하지 않는다.
3. 사용자가 생성을 요청하면 job을 만들고 진행·실패·재시도 상태를 보여준다. 완료한 결과가 backlog에 들어간다.
4. 상세 화면에서 SKILL.md, 참고 문서, 스크립트를 파일별로 읽고 수정한다. 생성 원본과 사용자 수정 버전을 보존한다.
5. 사용자가 검토 후 승인하면 active가 된다.
6. 사용자가 연결된 GitHub 또는 다른 목적지로 옮긴 뒤 merged로 표시한다. 다운로드만으로 이동 완료를 추정하지 않는다. 원본 패키지와 이력은 여기에도 남는다.
7. 시기가 지나거나 근거가 바뀌어 재검토가 필요하면, 사용자가 같은 레퍼런스의 상태를 merged/active에서 backlog로 되돌린다. 별도 레퍼런스나 승인 대기용 사본을 만들지 않는다. 문서 관리 상태와 근거의 변경 여부를 따로 표시한다.

## 문서 상태

| 상태 | 의미 | 전환 주체 |
| --- | --- | --- |
| backlog | AI 생성 완료 후 검토 전이거나 사용자가 재검토 대상으로 되돌린 레퍼런스 | 최초 생성 성공 또는 사용자 상태 변경 |
| active | 사용자가 검토하고 승인한 결과 | 사용자 승인 |
| merged | 외부 목적지에 옮긴 결과라고 사용자가 표시 | 사용자 설정 |

backlog는 생성 요청 대기열을 뜻하지 않는다. 작업 중인 job과 실패한 job은 생성 진행 목록에서 보여주며 완성된 레퍼런스로 취급하지 않는다. merged는 삭제·보관 종료·영구 검증 완료를 뜻하지 않는다. 세 상태 모두 열람·관리 대상이다.

## 작업 상태와 분리

생성 작업은 기존 queued/running/ready/failed/interrupted 계약을 사용한다. 문서 상태는 backlog/active/merged다. ready는 생성 성공이며 사용자 승인이나 외부 이동을 증명하지 않는다. 생성 실패 시 이전 문서와 승인 기록을 덮어쓰지 않는다.

문서의 현재 상태는 레퍼런스 하나에 둔다. 사용자 승인과 상태 변경 시점, 생성/수정 시각과 근거 변경 여부를 확인할 수 있어야 한다. 수정 이력과 외부 이동 기록은 남기되 별도 승인 버전이나 사본을 관리하는 흐름은 만들지 않는다. 검토 주기나 자동 상태 전환은 아직 정하지 않았으므로 추가하지 않는다.

## 외부 연결

연결 대상은 GitHub 또는 다른 목적지다. FS(frontend-system)는 유력한 후보지만 저장소·디렉터리·연동 계약은 미정이다. 현재 GitHub 연결이 있다는 이유만으로 자동 업로드하거나 PR을 만들지 않는다. 사용자가 merged를 설정하는 도메인과 외부 전송 성공 여부는 분리한다. 외부 전송 자동화는 목적지 계약을 확인한 뒤 구현한다.

## 현재 코드와의 차이

- 현재 TechnicalReferences는 사용자 설명과 AI 설명을 분리한 문서 목록이며, ReferenceSkill이 별도의 생성·ZIP 다운로드를 담당한다.
- 현재 패키지에는 SKILL.md, references/REFERENCE.md, provenance.json만 있고 생성된 스크립트와 패키지 파일 편집은 없다.
- 현재 생성 job 상태는 있으나 문서의 backlog/active/merged, 버전 승인·이동 기록은 없다.
- LearningTargets의 학습 선택과 versioned snapshot, 소유자 경계, 요청 중복 방지, job 이력은 재사용할 수 있다.
- 레퍼런스용 추천 목록과 학습 기록에서 바로 패키지를 만드는 진입이 필요하다. 홈의 다음 학습 제안을 그대로 레퍼런스 추천으로 간주하지 않는다.

## 확정된 상태 변경 규칙

2026-11-18 사용자 확인: 새 버전을 backlog 항목으로 분리하지 않는다. 같은 레퍼런스의 ID와 상세 페이지를 유지하고, 현재 merged인 레퍼런스도 사용자가 backlog로 상태만 변경할 수 있다. 재검토 후에는 같은 항목을 active로 승인하고 외부 반영 후 merged로 표시한다. 내용 수정 이력은 보존하되 새 레퍼런스 생성이나 승인 대기용 사본 생성과 구분한다. 수정·재생성 또는 근거 변경을 이유로 상태를 자동 전환하지 않는다. 기존 데이터에 승인/이동 이력을 임의로 부여하지 않는다.

## 구현 시 확인할 동작

- 학습 목록·직접 선택·추천 선택과 생성 job의 소유자 경계를 확인한다.
- 최초 AI 생성 성공 시 backlog가 된다. 기존 항목의 재검토는 사용자 상태 변경으로 처리하며, 수정·재생성으로 항목을 복제하거나 상태를 자동 변경하지 않는다. 실패·중복 요청·재시도에서도 기존 결과와 상태를 보존한다.
- 파일별 편집에 revision 충돌과 유실 방지를 적용한다. 패키지 파일 경로의 절대 경로·상위 디렉터리 이동·중복을 거부한다.
- ZIP의 파일과 화면의 선택 버전이 일치한다. 생성 스크립트를 자동 실행하지 않는다.
- 승인과 merged 설정, backlog로 되돌리기는 명시적 사용자 행동이며 동일 레퍼런스 ID를 유지한다. 다운로드·외부 링크 열기로 상태가 바뀌지 않는다.
- 기존 레퍼런스와 생성 이력을 마이그레이션 후에도 열람·내보낼 수 있다.

## 구현과 검증 · 2026-11-18

- 레퍼런스 목록에 상태 필터·검색을 제공하고 학습 목록에서 바로 생성한다. 추천은 최근 방문·실습 제출·남겨둔 질문에 근거한 규칙 기반이며 각 행에 이유를 표시한다. 단순 조회로 AI를 호출하지 않는다.
- Skill 생성은 기존 job·소유자 검사·중복 요청 방지·횟수 제한을 재사용한다. 추가 참고 문서와 스크립트 생성을 지원한다. 스크립트는 저장·미리보기·내보내기에서 실행하지 않는다.
- 파일별 Markdown/코드 열람, 추가·삭제·편집·초안 복구, revision 충돌 방지와 명시적 최신 파일 다시 불러오기를 구현했다. 경로/용량/Skill 헤더/내부 링크를 서버에서 검증한다. 헤더는 name과 한 줄 description을 지원한다.
- 상태 변경과 외부 반영 위치는 같은 ID에 저장한다. 수정과 재생성으로 상태가 자동 변경되지 않는다. 변경 이력은 문서 복사본이 아닌 같은 레퍼런스의 기록이다.
- 기존 완료 Skill은 backlog로 이관한다. 기존 수동 설명과 AI 설명은 ‘근거·이전 설명’에서 보존한다. 생성 도중 패키지나 근거가 바뀌면 파일을 덮어쓰지 않고, 완료 결과를 열람한 뒤 명시적으로 적용할 수 있다.
- 현재 ZIP과 전체 기록 내보내기에 패키지 파일·근거 스냅샷·변경 이력을 포함했다. 큰 근거 본문은 참고 문서에 발췌하고 생성 시점 스냅샷을 provenance.json에 보존한다.
- 검증: CI와 같은 백엔드 전체 287개 통과 후 추가 경계 검사 포함 관련 15개 통과. 프런트 33개, lint·build 통과. 브라우저 1440/768/390px 목록·생성·상세 9건과 승인/merged/재검토·파일 편집·충돌/초안 복구·생성 실패/진행 상태를 검사했다. [검사 코드와 화면](reference-skill-evidence/README.md)을 참조한다.
- 미실행: 실제 유료 AI 품질, 생성 스크립트 실행, GitHub/FS 전송, 운영 배포. 모든 생성·수정 브라우저 검증은 격리한 fixture를 사용했다. 실제 로컬 프리뷰는 세션·목록·근거 목록 읽기만 확인했다.
