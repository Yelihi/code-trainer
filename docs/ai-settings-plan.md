# 사용자별 AI 연결

기존 사용자 요구: AI API Key 등록. 전체 남은 기능 구현 및 release 병합, 사용자별 키도 포함한다는 후속 답변에 따라 진행한다.

- 서버가 지정한 API 주소를 화면에 표시하고 본인의 키와 모델을 저장한다. 키는 암호화하며 응답·로그·브라우저 저장소에 남기지 않는다. 저장은 유료 연결 검사가 아니다. 실제 생성 시 인증/모델 오류를 안내한다.
- 로컬의 기존 서버 환경설정은 등록 전 과도기 연결로 명시한다. 개인 키 등록 후 삭제하면 AI 연결을 해제하고 공통 키로 복귀하지 않는다. 운영 모드에서는 개인 설정이 없으면 AI 요청을 중지한다. 공개 가입·다중 사용자 운영은 이번 범위가 아니다.
- 저장한 연결에는 API 주소·모델·설정 버전을 함께 묶는다. 키 교체·삭제는 다음 요청부터 적용하고 이미 전송한 요청은 취소됐다고 표시하지 않는다. 키가 없거나 잘못됐다고 타인/공통 키로 재시도하지 않는다.
- 버전 충돌은409로 보존한다. 동일 저장 재전송은 중복 버전을 만들지 않는다. 삭제는 키를 지우되 해제 상태/설정 버전은 남긴다.
- 모든 호출자에 owner를 전달하고 실제 요청의 모델/설정 버전을 사용량에 기록한다. 해석·질문지·후보의 모델 출처도 실제 호출에 맞춘다. AI가 해제되어도 원문·요약 저장과 기존 코드 실습은 계속 사용할 수 있다.
- 암호화는 기존 Fernet 패턴을 재사용한다. TRAINER_AI_ENCRYPTION_KEY를 우선 사용하고, 없으면 기존 TRAINER_GITHUB_ENCRYPTION_KEY를 사용한다. 암호화 키가 없으면 개인 키 저장 불가를 명시한다. 서버 운영자는 해당 키를 백업해야 한다.

변경: AI 설정 모듈/입력/인증 API/DB 초기화, ai.py·usage.py 및 전체 AI 호출자, 설정 페이지/라우트/메뉴, 환경설정 예시와 CI 테스트 목록. 기존 api/useResource/네이티브 form 재사용. 새 의존성 없음.

검증: 소유자 격리/암호화/키 비노출/충돌/재전송/삭제 후 대체 없음, 모의 제공자의 실제 Authorization·모델·사용량·설정 버전, 요청 도중 교체/삭제 및 후속 중지, 기존 모든 AI 호출자 회귀, frontend 검사와 격리 실제 브라우저 설정 흐름. 실제 개인 키나 유료 AI 요청은 사용하지 않는다.
