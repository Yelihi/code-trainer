# 구독 글 자동 수집 적합성 검토

2026-10-06. 읽기 전용 검토이며 메일 계정 연결, 정기 수집, 자료 자동 생성은 설정하지 않았다.

## 실제 확인

제공한 `/subscribe?...&next=...`는 구독 화면 주소다. 실제 글 주소는 https://kofearticle.substack.com/p/korean-fe-article-55f 이다. 인증 없는 HTTP 요청으로 글과 https://kofearticle.substack.com/feed 를 확인했다. RSS는 HTTP 200, 최근 글 20개와 HTML 본문을 제공했다. 전체 과거 글이나 유료 글의 가용성은 확인하지 않았다.

예시 글 제목은 “[Korean FE Article] 빅테크에서 프로젝트를 출시하는 방법”이다. 현재 앱의 SSRF 방어가 적용된 `source.fetch`로 2,037자의 본문을 추출했으며 코드 예제는 0개였다. 본문은 소개·팀 의견과 원문 링크를 포함한다. 따라서 뉴스레터 글을 수집했다고 원문 전체를 수집했다고 간주하면 안 된다. 추출한 글을 AI에 전송하지 않았다.

## 판단

**RSS로 후보를 모으는 것은 적합하다. 모든 글을 즉시 코드 문제로 생성하는 것은 현재 앱에 적합하지 않다.** 현재 생성기는 실행 가능한 작은 언어 개념을 대상으로 하며 프로젝트·웹앱·패키지 의존 문제를 제외한다. 예시처럼 조직·출시 절차·의견 중심인 글, React 렌더링/브라우저 동작을 요구하는 글은 현재 실행 환경과 맞지 않을 수 있다.

제안 흐름은 `허용한 RSS → 링크/제목/짧은 소개 보관 → 적합성 분류 → 사용자가 선택 → 개념 과정 생성 → 원하는 단원 문제 생성`이다. 자동 수집에는 AI가 필요 없으며, 제목·코드 존재 여부만으로 최종 적합성을 확정하지 않는다. 초기에는 사용자가 원문과 목표 언어를 확인한다. 품질이 확인된 출처만 나중에 하루 최대 1개 등의 명시적 한도로 자동 생성을 허용한다.

## 추후 구현 조건

- RSS GUID와 정규화한 글 URL로 중복 수집 방지. 원문 링크 이동은 사용자 선택 또는 허용한 도메인에 한정하고 매 redirect마다 현재 공개 IP 검사 재사용.
- 이메일 개인 추적 쿼리·수신자 식별자는 제거한다. 임의의 `next` 파라미터를 무조건 따라가지 않는다.
- 로그인/유료 접근이 필요한 글은 건너뛴다. 공개 RSS라고 재배포 허용을 뜻하지 않으므로 원문 보관·AI 전송·공유 범위는 해당 출처 정책에 맞춰 별도로 결정한다.
- 최대 응답 크기·timeout·폴링 간격·실패 재시도 상한을 두고, XML 외부 엔티티를 처리하지 않는다. 수집기에는 앱 실행기나 Docker 권한이 필요 없다.
- 자동 생성은 사용자별 호출 상한·중단 스위치·생성 실패 기록이 선행돼야 한다. 이번에 추가한 토큰 집계는 과금 상한을 강제하는 기능이 아니다.
- 이메일 본문 직접 수집은 RSS가 없는 발행처에 한해 별도 검토한다. 메일 읽기 권한·필터·첨부/개인정보 처리·OAuth 관리가 추가되므로 이 예시에는 RSS가 더 단순하다.

관련 공개 주소: [뉴스레터 글](https://kofearticle.substack.com/p/korean-fe-article-55f), [RSS](https://kofearticle.substack.com/feed). 현재 접근 가능성만 확인했으며 장기 제공을 보장하지 않는다.
