# P7 해석 섹션에서 코드 실습으로

전체 release 완결 및 추천 방향 진행 요청에 따라 기존 P7을 구현한다. 해석 문서에서 섹션별 코드 실습 링크를 열고 언어·난이도를 선택한다. 먼저 선택한 섹션으로 코딩 학습 과정을 준비한 뒤 기존 단원별 문제 생성·정답/오답 실행 검증·풀이 경로를 그대로 사용한다. 분석이 실제 검증된 문제인 것처럼 표시하지 않는다. 코딩에 부적합한 내용은 기존 분석기의 이유 있는 실패를 보여준다.

서버는 본인 소유의 완료된 해석과 유효한 섹션만 받는다. 원문 버전, 해석 ID, 섹션 ID와 제목, 요청 언어·난이도를 작업 출처로 고정한다. AI에는 해당 원문 버전과 선택 섹션의 AI 해석을 구분해 전달한다. 입력 본문을 클라이언트에서 임의 전달하거나 현재 원문으로 바꿔치기하지 않는다. 새 원문 버전이 생겨도 과거 해석의 실습 출처는 유지한다. 일반 해석/질문지는 변경하지 않는다.

동일 요청 ID는 동일 섹션·언어·난이도만 재생한다. 겹치는 생성은 기존 서버 작업 잠금으로 차단하며 실패 뒤에는 명시적 새 요청으로 재시도한다. 섹션별 생성 기록을 조회할 수 있고 조회만으로 AI를 호출하지 않는다. 기존 학습 과정·단원 화면에는 원문 버전 및 해석 섹션으로 돌아가는 출처 링크를 보여준다. 과정 삭제 시 작업 연결만 정리하고 원문/해석은 보존한다.

변경: backend/schema.py, service.py, db.py, api.py와 신규 code_practice.py 및 테스트. frontend/Interpretations.tsx, 신규 InterpretationCode.tsx, Learning.tsx, api.ts, main.tsx. 기존 Select/GenerationStatus/API/자료·해석 UI 재사용. 새 의존성 없음.

검증: 잘못된 owner/미완료/섹션/입력 거부, 요청 재전송·충돌·동시 요청·실패, 원문 변경 중 출처 보존, 기존 단원 생성 실행 검증/출처/삭제 회귀. 프론트엔드 테스트·타입·린트·빌드 및 실제 격리 브라우저에서 섹션 이동→언어/난이도→과정 준비→단원→문제 이동, 오류·재열기·모바일 확인. 실제 유료 AI 요청은 하지 않는다. 기존 샌드박스 실행 검증은 CI에서 수행한다.
