## 기준 문제의 평가 범위

출처: [MDN Closures](https://developer.mozilla.org/en-US/docs/Web/JavaScript/Guide/Closures). 저장하는 Context·문제·대안 풀이·대표 오답은 `backend/sample.py`에 있다.

| 단계 | 자동 확인 | 다른 풀이 / 대표 오답 |
| --- | --- | --- |
| READ | 독립적인 두 카운터의 출력 `1 2 11 3` | 실제 실행과 예상 답변 비교 |
| FIX | 시작값 누적, 인스턴스 간 독립성 | 배열을 사용하는 대안, 증가하지 않는 코드·공유 전역 상태 코드 |
| MODIFY | 양수·0·음수 간격, 인스턴스 독립성 | 호출 횟수로 계산하는 대안, 항상 1 증가·공유 상태 코드 |
| BUILD | 잔액 누적, 양수·0·음수 변화, 독립성 | 배열 상태 대안, 절댓값만 더하는 코드·공유 잔액 코드 |

모든 코드 문제에서 기준 풀이·대안 풀이가 공개·비공개 테스트를 통과하며, 각 요구사항의 대표 오답은 지정 테스트에서 출력 불일치로 실패한다. FIX starter도 의도한 출력 불일치가 확인된다.

클로저 문법 사용 자체, 설명의 교육적 품질, 실제 이해도는 stdout 테스트로 판정하지 않는다. 배열 기반의 올바른 대안도 허용한다.

- 수정 전 임시 DB에서 FIX 풀이 수정 → 제출 통과 → 다음 1회 클릭 시 같은 FIX에 남는 현상을 재현했다. 저장 Promise 직후 이동하면 렌더 전의 미저장 상태로 `useBlocker`가 막았다. 이제 저장 상태가 반영된 effect에서 이동한다. 수정 후 같은 순서의 다음 1회 → MODIFY, 이전 → 저장 코드 유지, 수정한 MODIFY → BUILD 탭 1회 이동을 브라우저 assertion으로 확인했다.
- 저장 API 503을 주입하면 URL·작성 내용 유지 및 재시도 가능, 오류 해제 후 다음 1회 이동을 확인했다. 테스트용 제출 판정과 실행 출력은 stub이며 실제 학습 데이터·AI를 사용하지 않았다.
- 신규 code-mode 문제는 MODIFY·BUILD도 시작 코드와 모든 테스트를 함께 실행한다. 미완성 출력은 허용하지만 문법/실행 오류는 거부한다. JS/TS/Python의 시작 코드 단독 실행에서 예시 출력이 있으면 거부하고 기존 생성 수정 흐름으로 보낸다. READ의 예측용 프로그램은 이 제한에서 제외한다. 기존 저장된 문제와 풀이를 자동 변환하지 않는다.
- `backend.test_app.AppTest.test_modify_and_build_starters_reject_test_collisions_and_demo_output`은 두 단계의 중복 선언/예시 출력을 거부하는 회귀 검사다. `scripts/check-sandbox.py`에는 함수 구현+별도 호출의 정상 출력, 같은 `plain` 선언 충돌, 다음 실행에서 변수 잔존 없음의 실제 Docker 검사를 추가했다. 브라우저에서는 중복 선언 오류 안내를 별도 stub으로 확인했다.
- 로컬 Python 79개, 프런트 API 3개·타입·lint·빌드 통과. Frontend System MCP 기록 도구는 연결되지 않아 해당 워크플로 완료 기록은 생성하지 않았다.
- 첫 CI의 실제 샌드박스 검사가 내장 BUILD의 빈 함수(반환 함수 누락)를 거부했다. 임시 `amount => 0` 반환으로 시작 코드를 보완했다. 정답 로직은 포함하지 않으며 기본 테스트는 미통과한다. Mac의 기존 mTLS 실행기를 통해 현재 소스의 기본 문제 검증 19개 통과, 관련 Python 51개 재검사 통과를 확인했다.

### 정답 코드 분할 비교 (2026-10-08)

- FIX·MODIFY·BUILD의 정답은 작성 편집기 옆 읽기 전용 CodeMirror로 표시한다. 기존 정답 API와 도움 사용 기록을 유지하며 READ는 정답 출력을 표시한다.
- 임시 DB의 로컬 브라우저에서 정답 열기·닫기 후 미저장 코드 보존, 정답 편집 불가, 좌우 동일 높이 배치, 상단 메뉴 아래로 이동을 assertion으로 확인했다. 390×844 화면에서는 코드 탭으로 전환해 위아래 배치하고 가로 넘침이 없으며, READ의 정답 출력 유지도 확인했다.
- 프런트엔드 빌드·lint 통과. 새 의존성이나 백엔드 변경은 없다.

### 설명글과 코드 구문 강조 (2026-10-09)

- 개념 설명·단계별 해설·이해 확인 답변·문제 설명은 CommonMark로 표시하고, 문단·목록·인용·인라인 코드의 간격과 색상을 조정했다. [react-markdown](https://github.com/remarkjs/react-markdown)의 기본 HTML 이스케이프와 URL 필터를 유지하며 외부 이미지는 대체 텍스트로 표시한다.

- `npm --prefix frontend test`는 실제 Markdown 컴포넌트의 구조, 코드 블록, HTML/위험 URL 처리, `<T>` 텍스트 보존, TypeScript 제네릭 문법을 검사한다. 4개 테스트와 타입·lint·빌드 통과.
- 별도 임시 DB의 브라우저에서 TypeScript 예제에 8개 구문 색상이 표시되고 읽기 전용인 것을 확인했다. 데스크톱과 390×844 모바일에 가로 넘침이 없고 공개 테스트의 코드 복사도 유지된다. 화면을 직접 검토했으며 운영 자료·AI 호출은 사용하지 않았다.
