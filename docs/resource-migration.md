# 원문 저장소 이행 (P1)

앱 시작 시 기존 스키마 초기화가 끝난 뒤 별도 쓰기 트랜잭션으로 이행한다.
기존 테이블과 API는 계속 사용한다.

- `resources`: 소유자와 원본 종류(`source`, `note`), 원본 ID로 식별한다.
  원본 생성 시각을 유지하며 학습 자료·생성 작업 삭제와 연결된 외래 키는 없다.
- `resource_versions`: 가져온 원문의 종류, 이름, URL, 본문을 그대로 저장한다.
  `NULL`과 빈 문자열을 구별한다. 최신 스냅샷과 달라질 때만 새 revision을 추가한다.
  이전 내용으로 되돌아와도 새로운 변경 이력으로 남는다. `created_at`은 스냅샷 저장 시각이다.
- 직접 작성한 노트는 소유자가 일치하는 `reference_notes`를 참조한다.
  기존 본문·이미지·`reference_note_versions`를 복사하거나 수정하지 않는다.
  보관된 노트도 식별자만 연결하며 보관/복원 및 그래프 정책을 변경하지 않는다.

학습 자료 삭제 시 소유권과 생성/채점 중 여부를 먼저 검사한다. 이후 해당 자료에
연결된 원문을 보존하고 기존 삭제를 수행한다. 어느 쪽이든 실패하면 같은 트랜잭션의
스냅샷과 삭제가 모두 롤백된다. 서버 시작 이후 추가된 원문도 이 경로로 보존된다.
기존 관리자 원문 API는 삭제 후 계속 404를 반환하며 새 저장소를 노출하지 않는다.

## 범위와 운영

이번 단계는 저장소 이행이다. 새 등록 화면/API는 P2에서 연결한다. 그전에는 원문
스냅샷이 시작/삭제 시점에 생성되므로 실행 중 모든 중간 편집을 기록하지는 않는다.
원문이 없는 샘플이나 이전 학습 자료에서 AI 해석문을 원문으로 복원하지 않는다.
기존에 이미 삭제된 원문도 복구할 수 없다.

운영 DB에는 이번 작업 중 이행을 실행하지 않았다. 적용 전에는 기존 백업 절차로
DB를 백업한다. 이행은 재시도 가능하며 실패는 숨기지 않고 시작/삭제를 중단한다.
영구 삭제 정책은 별도 설계 대상이고, 이 단계의 원문은 학습 자료 삭제 후에도 남는다.

검증: `.venv/bin/python -m unittest backend.test_resources -v`.
임시 DB에서 중복 이행, 변경 이력, 삭제 후 보존, 실패 롤백, 소유권/실행 중 차단,
원문 없는 자료를 검사한다. CI의 기존 백엔드 회귀 테스트 목록에도 포함된다.
