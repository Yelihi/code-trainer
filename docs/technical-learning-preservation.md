# 기록 보존과 복구

## 사용자 기록

`GET /api/records/export`는 로그인한 소유자의 원자료/버전, 질문/꼬리질문/가이드, 풀이/제출/도움 사용, 복습 일정/초안, 노트/이미지/개념 근거, 기존 위키/개인 기록/전체 버전을 UTF-8 JSON ZIP으로 제공한다. ID와 참조를 보존하고 바이너리 이미지는 base64로 표시한다. `manifest.json`에 테이블별 개수와 제외 범위를 기록한다. 비밀번호, 세션, AI 키, GitHub 자격증명, 다른 소유자 기록은 포함하지 않는다.

이 파일은 사람이 읽고 다른 도구로 처리할 수 있는 기록이다. 자동 DB 가져오기 기능은 제공하지 않는다. 위키 Markdown ZIP도 유지하며 `history/`에 전체 페이지 버전을 추가했다.

## 전체 백업과 복원

운영자의 전체 복구에는 `TRAINER_DB=/path/to/live.sqlite3 python scripts/backup.py /private/new-backup.sqlite3`를 사용한다. SQLite backup API로 일관된 스냅샷을 만들고 무결성을 확인하며 권한은 0600이다. 기존 백업은 덮어쓰지 않는다. 전체 DB에는 자격증명이 포함되므로 암호화된 운영 백업 저장소를 이용한다.

복원은 서비스를 중단하고 현재 DB와 WAL/SHM을 별도 보관한 뒤, 백업을 **새 경로**로 복사하고 `PRAGMA integrity_check`, `PRAGMA foreign_key_check`를 확인한다. `TRAINER_DB`를 새 경로로 지정해 서비스를 시작한다. 문제가 있으면 서비스를 중단하고 이전 경로로 되돌린다. 운영 DB를 개발 테스트에 사용하지 않는다.

검증: `backend.test_record_export`는 임시 DB에서 사용자 질문과 다른 소유자 기록을 생성하고 ZIP 재열기/소유자 격리/자격증명 제외를 검사한다. 실제 백업 스크립트로 생성한 스냅샷을 별도 DB에 복원하고 질문 본문, FK, 무결성, 파일 권한을 확인했다. 위키 회귀 9개도 통과했다. 운영 장치 전체 재부팅과 다른 기기 복원은 이 검증에 포함하지 않는다.

## 제외 기능 정리 전 확인

삭제할 데이터 테이블은 없다. 기존 위키/개인 기록은 내보내기와 전환 화면을 통해 접근한다. `insight_schedule.poll`은 범용 Deep Inside 유료 생성 예약이므로 단계 13에서 중단한다. RSS 수집, 배포, 모니터, 암호화 백업 예약은 유지한다. 공유 ontology와 학습/복습/질문 로직은 제거하지 않는다.
