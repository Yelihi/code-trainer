# 원문 등록과 자료 보관함 (P2)

`/library`에서 텍스트·Markdown, UTF-8 `.md`/`.txt`, 웹 URL과 직접 작성한 노트를 조회한다. 등록은 AI와 실행 샌드박스를 호출하지 않는다. 기존 노트 편집·이미지·그래프·보관 기능은 `/references`에서 유지한다.

## 본문 버전

- URL은 사용자별로 입력 주소의 앞뒤 공백만 제거해 비교한다. 쿼리·프래그먼트·리다이렉트 결과를 임의로 합치지 않는다.
- 동일 URL을 다시 등록하면 기존 자료를 사용하고, 안전한 기존 수집기로 얻은 **본문 문자열이 달라졌을 때만** 새 버전을 추가한다. 텍스트 편집도 같은 비교를 쓴다. 공백과 줄바꿈의 차이도 본문 변경이다.
- 제목 등 현재 메타데이터는 따로 저장한다. 제목만 변경하면 본문 버전은 그대로이며, 기존 버전의 제목·본문은 바꾸지 않는다.
- 수집 실패는 URL과 오류를 남긴다. 마지막 정상 본문은 유지하며, 최초 실패 자료에는 본문 버전이 없다.
- 노트의 기존 버전 정책은 유지한다. 노트 저장과 보관함 연결은 같은 트랜잭션에서 처리한다.

## 저장·재시도 경계

`POST /api/resources`는 `request_id`, `kind`, `name`, `content` 또는 `url`을 받는다. 텍스트 수정은 `resource_id`와 읽었던 `revision`을 함께 보낸다. 조회는 `GET /api/resources`, `GET /api/resources/{id}`, `GET /api/resources/{id}/versions/{revision}`이다. 모든 조회·수정은 로그인한 소유자에게 제한한다.

동일 요청 ID와 동일 입력은 저장된 응답을 재사용하고 재수집하지 않는다. 같은 ID로 입력을 바꾸면 409다. 새 수집은 사용자 동작으로만 실행한다. 수집 중인 자료의 다른 요청은 409로 막고, 네트워크 작업 동안 SQLite 쓰기 잠금을 유지하지 않는다. 중단된 수집은 최대 120초 후 새 요청으로 재시도할 수 있다. 늦은 이전 응답은 새 요청 결과를 덮어쓰지 않는다. 완료 기록과 새 본문 버전은 한 트랜잭션으로 저장한다.

P1에서 이전한 자료와 기록을 삭제하거나 병합하지 않는다. 처음 URL을 등록할 때 기존 동일 URL 중 가장 이른 자료 하나를 연결한다(동일 시각은 ID 순서). 다른 사본은 남기고, 이미 연결된 URL의 사본을 직접 갱신하려 하면 409로 안내한다. 등록 경로가 맡은 자료는 이후 시작/삭제 시점의 레거시 스냅샷으로 되돌리지 않는다.

## 화면과 검증

폼은 소유자별 브라우저 임시 글과 요청 ID를 보존한다. 등록 방식 전환 시 입력을 지우지 않고, 파일은 UTF-8 및 본문 60,000자 제한을 검사한다. 저장 실패 시 입력이 남으며, 화면 이동에는 미저장 확인을 제공한다. 상세에서 URL 재수집·텍스트 수정·과거 버전 조회를 제공한다. 검색·종류·페이지는 URL에 기록한다.

검증: `python -m unittest backend.test_resources backend.test_reference_notes backend.test_app backend.test_learning_features -q`; 프론트엔드 `test`, `typecheck`, `lint`, `build`. 브라우저에서는 개발 DB에서 `[P2 검증]` 자료로 등록·제목 변경·본문 변경·과거 버전·임시 글 복원·실패 재시도·검색과 모바일 화면을 확인한다.

범위 밖: 원문 삭제/보관, RSA 전환, AI 해석, 사이드바 전체 재편. release 검토 전 main 배포는 수행하지 않는다.
