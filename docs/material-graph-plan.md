# P10 검토한 후보를 그래프에 등록

사용자가 추출된 후보의 정의·범위·인용·관계를 수정하고 개념마다 기존 개념 재사용 또는 별개 개념을 선택한 뒤 명시적으로 등록한다. 기존 ReferenceKnowledge의 후보 편집·비교·명시 선택 UI를 재사용하며 실제 note와 reviewed material 호출자를 구분한다. 가짜 노트나 AI 해석의 원문 복제본을 만들지 않는다. 기존 노트의 직접 입력·본문 수정 제안·등록 흐름은 유지한다.

새 등록은 review ID와 정확한 원본 종류/ID/버전, 최신 완료된 proposal을 확인한다. 미완료·실패·내용 검토 이슈·변경/보관된 자료는 등록할 수 없다. 원문과 다른 인용, 다른 owner의 개념/후보, 의미가 다른 동일 요청 ID, 이미 등록한 같은 버전은 거부한다. 요청 재전송은 저장 결과를 반환한다. ontology.validate_proposal/register의 개념 ID·관계·순환 검증을 재사용하고 출처·개념·근거·관계·등록 영수증은 한 트랜잭션이다. 새 자료의 근거는 interpretation 또는 question이며 원문 직접 주장으로 바꾸지 않는다.

knowledge_sources에는 interpretation/practice 종류와 실제 원본 ID·버전을 넣고 metadata에 확인 ID, 원문 ID/버전, 작성 주체를 남긴다. 사용자 답변·요약 등록은 실제 작성 시각과 연결 개념을 learning_observations의 self_explanation으로 기록한다. AI 해석 등록은 수행 관찰을 만들지 않는다. 등록은 숙달·코드 통과·복습 일정이 아니다. 같은 등록 재전송에 관찰이 늘지 않는다.

본문 버전 저장과 같은 트랜잭션에서 관련 active 근거를 stale로 바꾼다. 원문 수정은 연결된 해석/실습의 근거를, 실습 수정은 해당 작성분의 근거만 바꾼다. 기존 노트 보관은 관련 파생 근거도 deleted, 복원은 stale로 둔다. 다른 출처와 개념 및 과거 관찰은 보존한다. 새 범용 이벤트 버스나 원문 영구 삭제는 도입하지 않는다.

그래프의 개념·관계 근거에 자료 종류/작성 주체/버전/검토한 자료 링크를 표시한다. 실제 설명 기록도 개념 상세에 보여주며 AI 설명과 구분한다. 기존 노트·기초/단원·GitHub 공유의 공개 범위를 유지한다. 이 단계에서는 새 자료별 그래프 노드 종류를 추가하지 않고 개념에 연결된 근거로 표현한다.

검증: 두 자료 종류 등록, 명시 선택/기존 ID, 정확 인용, 검토 이슈/구버전/소유권 거부, 재전송/동시 등록/순환 롤백, 원문·작성분·보관 상태 변경, AI 관찰0/사용자 관찰과 재전송 중복0, 기존 노트·그래프·공유 회귀. 실제 브라우저 후보 편집→개념 선택→등록→그래프 출처/관찰 링크, 오류 보존 및390px 확인. 실 AI·운영 DB를 사용하지 않는다.
