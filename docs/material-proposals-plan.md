# P9 검토한 자료에서 근거 있는 후보 추출

P8에서 확인한 해석·사용자 작성분의 정확한 버전을 대상으로 사용자가 AI 후보 생성을 요청한다. GET은 AI를 호출하지 않는다. 소유권과 현재 적격 상태를 확인하고 요청 ID 재전송은 동일 작업으로, 동시 요청은 진행 중인 작업 하나로 연결한다. 입력이 다른 같은 요청 ID는409다. 실패·서버 재시작은 자동 유료 재시도하지 않고 기록을 남긴다.

기존 reference_notes의 추출→인용 보정→정확성 검토→온톨로지 검증을 하나의 공유 함수로 옮겨 새 호출자가 재사용한다. 기존 노트의 프롬프트와 오류 처리는 보존한다. 새 자료에는 작성 주체를 전달하며 AI 해석/사용자 답변을 원문 자체의 주장으로 승격하지 않는다. 새 자료의 source 근거 성격은 interpretation으로 제한하고 question은 유지한다. 이름만 같은 개념은 자동 합치지 않는다.

기존 knowledge_proposals는 note FK가 강제되어 있으므로 가짜 노트를 만들거나 기존 테이블을 재구축하지 않는다. material_proposals가 material_reviews를 참조하면 종류·원본 ID·버전은 그 검토 기록에서 얻는다. 이는 같은 추출 모델/검증을 사용하는 새 출처 어댑터다. 결과는 요청했던 버전에 붙이며 완료 시 원문/작성분이 바뀌거나 보관되었으면 stale로 표시한다. 다시 시작한 프로세스의 중단 작업은 늦게 온 결과가 덮어쓰지 않는다. 모델/사용량은 실제 호출 설정에 연결한다.

추출 가능 상세에서 생성 요청, 진행/실패/이전 결과, 개념·정의·범위·정확한 인용·관계·내용 검토·기존 개념 추천을 읽는다. 화면 종료 시 조회 폴링을 정리한다. 새로고침 후 현재 작업을 다시 읽으며 네트워크 실패에 자동 POST하지 않는다. 원문 수정이 필요하면 원래 학습 화면을 안내한다. 후보 편집·명시 선택·그래프 등록은 P10에서 연결하며 P9는 그래프를 쓰지 않는다.

검증: 기존 노트 추출 회귀, owner·미검토·stale 거부, 재전송/동시 요청과 결과 유실, 인용 오류 보정/거부, 작성 주체 강제, 완료 중 원문 변경 및 재시작, 모델/사용량 연결. 프론트엔드 필수 검사와 실제 격리 브라우저에서 생성·실패·다시 열기·모바일을 확인한다. 실 AI 호출은 하지 않는다.
