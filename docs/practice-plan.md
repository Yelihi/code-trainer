# P6 질문지·답변·요약 — 상세 제안

기준: release/second-brain-redesign 7132c8c. 작업 브랜치 feat/interpretation-practice.
사용자의 “나머지도 계속 진행하겠습니다”에 따라 다음 단계의 관련 코드를 조사했다.
기존 요구의 AI 생성 질문지를 기준으로 별도 질문지 생성안을 제안한다.
2026-10-25 사용자가 위 상세 계획과 화면 흐름도를 제시받은 뒤 “진행해주세요”라고 답하여 별도 질문지 생성 및 답변·요약 저장 상세안을 승인했다.

1. P6a: 완료된 일반 해석에서 사용자가 실습용 질문지를 생성한다. 기존 확인 질문을 보존한다. 질문은 해석 섹션에 연결하고 원문·해석 버전을 고정한다. 생성 대기/진행/실패/중단과 명시적 재시도를 처리한다. 생성 기록을 실습하기에서 다시 연다.
2. P6b: 질문지별 내 답변과 요약을 별도 학습 기록으로 저장한다. 일부 답변만으로 저장할 수 있으며 자동 정답이나 채점을 요구하지 않는다. 동일 질문지의 작성분을 이어 수정하되 변경된 내용만 새 버전으로 보관한다. 다른 질문지는 별도 기록이다.

질문지 생성과 작성분 저장은 서로 다른 사용자 동작이므로 각각 UI·API·저장·테스트를 포함한 두 PR로 분리한다. 둘 다 release를 대상으로 하며 main 병합·배포는 최종 확인 뒤에 한다.

화면: 해석 상세에 생성 버튼과 기록 링크, 실습하기에 질문지 목록, 질문지 상세에 출처와 질문, 작성 화면에 질문별 답변·요약·저장 상태. 네이티브 입력/버튼과 기존 Markdown/요청 함수를 사용한다. 새 라이브러리는 필요 없다.

보존: 서버가 owner를 정하고 소유권을 검사한다. 요청 재전송은 같은 작업/저장으로 처리한다. 작성분은 owner+질문지 키로 임시 보관하고, 저장 실패/인증 만료/동시 수정 충돌에 보존한다. 오래된 서버 응답은 새로 입력한 내용을 지우지 않는다. 충돌 시 최신본 확인을 제공하며 자동 덮어쓰지 않는다. 브라우저 저장소 차단은 명시적으로 알린다.

범위 밖: 코드 문제(P7), 검토 완료/추출 적격(P8), 그래프 등록, 복습 일정, 사용자 AI 키, Deep Inside, 이미지 첨부 신규 지원, 자동 평가. 기존 노트/코드 실습 기능은 유지한다.

검증 계획: backend/test_worksheets.py 및 backend/test_practice_records.py에서 버전 고정·소유권·동시 요청·재전송·재시작·실패·저장 충돌 검사. 프론트 test/typecheck/lint/build와 기존 API/노트/해석 회귀. 임시 DB/통제된 제공자로 실제 브라우저에서 실패→재시도, 일부 작성→저장→재열기, 세션/네트워크 실패, 충돌, 모바일·키보드 확인. 실제 유료 AI 생성은 검증에 포함하지 않는다.

미완료: P6 제품/테스트 구현과 실행 검증. FS 전체 분석은 partial로 유지한다.
