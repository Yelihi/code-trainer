# 레퍼런스 노트

## 사용자 흐름

1. **레퍼런스 노트 → 새 노트 작성**: 제목·Markdown 본문 작성, 서식 버튼, 미리보기, 이미지 선택·붙여넣기·드래그 첨부.
2. 책/강의/글/직접 경험의 출처 이름·저자·URL·페이지/회차를 선택적으로 기록한다.
3. **노트 저장**을 눌러 서버에 저장한다. 작성 중인 글은 계정·노트별 브라우저 임시 저장이며 서버 저장과 다르다. 이탈 경고와 낙관적 버전 검사를 제공한다.
4. **개념 지도에 추가하기** 탭에서 **AI로 후보 생성·내용 검토** 또는 수동 입력을 사용한다. AI는 후보 추출 후 별도 요청으로 본문과 후보의 정의·주장·관계를 검토한다. 본문에서 발견한 문제는 원문 인용·이유·수정 제안과 함께 표시한다. 수정/추가 확인이 필요한 본문은 사용자가 수정·저장한 뒤 새 버전에서 다시 검토해야 등록할 수 있다. 기존 개념 ID 선택, 새 개념·별칭·정의·범위, 주장/방향 관계, 원문 근거, 출처 정리/나의 해석/미해결 질문, 지지/반박을 확인한다.
5. **검토한 내용으로 개념 지도에 추가하기**를 눌러 확정한다. 저장·열람·AI 후보 생성·복습 답변은 그래프에 자동 등록되지 않는다.
6. **내 말로 설명해보기**: 첫 질문에 설명을 제출하면 답변을 먼저 저장하고 AI가 연결된 노트를 바탕으로 한 가지 꼬리 질문을 만든다. 코드 작성은 요구하지 않는다. AI 실패 시 같은 답변으로 재시도한다.
7. 지식 그래프의 노트/개념 상세에서 근거·버전·주장·관계·연결된 노트를 확인한다. 이전 문제 링크는 계속 제공한다.

## 공통 온톨로지 저장 계약

`docs/knowledge-graph-plan.md`의 Concept / Alias / Claim 및 typed Edge / Evidence / LearningObservation 분리를 SQLite로 구현한다. RDF 엔진이나 SHACL 실행기를 도입한 것은 아니다. 타입/필수값/소유자/참조/방향/순환 검사는 Pydantic, SQLite 복합 외래 키, 애플리케이션 검증으로 수행한다.

| 테이블 | 계약 |
| --- | --- |
| `reference_notes` | 현재 제목·본문·출처 메타데이터·리비전. 저장은 명시적이며 이전 리비전 수정은 409. |
| `reference_note_versions` | 명시적 저장마다 불변 스냅샷. 수정 이전 본문과 첨부 참조 유지. |
| `reference_images` | 소유자별 이미지 BLOB. 기존 SQLite 백업에 포함된다. SVG/외부 URL 이미지는 렌더링하지 않는다. |
| `knowledge_sources` | 출처 종류·원본 ID·버전·본문·메타데이터. `active`, `stale`, `deleted`로 근거의 현재 유효성을 구분. |
| `knowledge_concepts` | 이름과 독립적인 영구 ID, 대표명·정의·범위·검토 상태. 같은 이름 자동 통합 금지. |
| `knowledge_aliases` | 확인한 별칭. 별칭이 같아도 서로 다른 의미일 수 있으므로 다른 개념 간 고유성을 강제하지 않음. |
| `knowledge_assertions` | `CLAIM`, `PREREQUISITE_OF`, `BROADER_THAN`, `USED_IN`, `RELATED_TO`. 마지막 관계는 대칭 정규화. 조건과 상충하는 주장은 별도로 유지. |
| `knowledge_evidence` | 개념/주장 중 하나, 출처 ID·버전, 정확한 인용 문장과 문자 위치, 근거 성격, 지지/반박. 출처 본문에 없는 인용 거절. |
| `knowledge_proposals` | AI 후보·내용 검토(summary/issues)·상태·모델·프롬프트 버전. 검토 결과는 기존 data JSON에 함께 보관하며 후보는 승인된 그래프와 분리. |
| `knowledge_registrations` | 명시적 승인 요청·수정된 payload·AI 출처·승인 시점의 내용 검토·기존 개념 정의·승인 시각. 같은 요청 재전송은 중복 등록하지 않음. |
| `reference_reviews` | 복습 시작 시점의 근거 발췌, 질문·사용자 설명·AI 피드백, 순서와 실패 상태. 노트가 변경돼도 기존 대화의 근거는 고정. |
| `learning_observations` | 등록된 개념에 대한 실제 자기 설명과 복습 ID. 노트 참고 가능 상태를 기록하며 숙달 점수를 만들지 않음. |

사용자 데이터의 조회는 owner로 제한한다. 그래프 테이블의 참조는 owner와 ID의 복합 외래 키를 사용한다. AI는 소유자가 접근 가능한 본문만 받으며, 참고서 원문이나 첨부 이미지 내용을 읽었다고 간주하지 않는다.

## 후보 생성 시 내용 검토

- `reference-ontology-v2`: 기존 온톨로지 후보 추출 → 별도 AI 요청으로 본문과 후보 검토 → 인용·참조 구조 재검증. 검토 실패 시 후보를 ready로 공개하지 않는다. 후보를 생성할 때 AI 호출이 2회 발생하므로 대기 시간과 사용량이 늘어난다.
- 본문은 맞지만 추출된 정의/관계가 잘못된 경우 원문 근거를 유지하면서 후보를 수정한다. 본문 자체에 오류가 있으면 잘못된 문장을 수정된 개념의 지지 근거로 사용하지 않는다. 본문은 자동으로 덮어쓰지 않는다.
- `correction_needed`: 식별 가능한 사실·논리 오류. `needs_verification`: 조건이나 자료가 부족해 판단하기 어려운 중요한 사실 주장. 둘 다 원문 인용·검토 이유·수정/확인 제안을 표시하고 본문 수정 후 재검토를 요구한다. 명시적 질문·개인적 감상·단순 표현 차이는 사실 오류로 취급하지 않는다.
- 같은 노트 버전의 미해결 검토는 재사용한다. 다시 생성 버튼을 누르거나 proposal_id를 생략하거나 수동 입력으로 전환해도 알려진 문제를 우회하여 등록할 수 없다. 등록 트랜잭션에서 서버에 저장된 검토를 확인한다.
- AI 검토를 시작한 노트는 현재 버전의 검토가 완료돼야 등록할 수 있다. 본문을 수정하면 이전 검토는 이전 버전에 남고, 현재 버전의 근거와 새 검토가 필요하다. 검토 전 v1 후보는 AI 후보를 다시 생성해야 한다. 처음부터 수동 입력하는 흐름에는 AI 검토 완료 표시를 하지 않는다.
- 검토의 원문 인용도 노트 본문과 정확히 일치해야 한다. AI 출력이나 클라이언트의 검토 결과를 새로운 출처 근거로 사용하지 않는다. 기존 그래프 개념도 절대적인 사실로 가정하지 않는다.
- AI 자체 지식에 기반한 검토이며 외부 웹/책/강의 원문을 조회하지 않는다. 오류 미발견은 사실 확인 완료를 의미하지 않는다. 사용자가 검토 이후 직접 편집한 후보는 별도 AI 재검토 없이 명시적으로 승인하는 값이다.

## 기존 개념 비교와 명시적 선택

- 각 후보에 이번 노트의 정의·범위와 기존 개념의 정의·범위·별칭을 비교하는 카드를 표시한다. AI 의미 비교 추천과 이름·별칭 검색 결과를 구분한다.
- AI 내용 검토 응답의 `matches`에는 후보 키·기존 개념 ID·추천 이유를 최대 3개씩 저장한다. 서버는 소유권, 후보 참조, 중복, 개수 제한을 확인하고 현재 저장된 개념의 정의를 응답에 붙인다. AI가 기존 개념의 정의를 만들어 표시하지 않는다.
- 이름·별칭 검색은 공백/대소문자/유니코드를 정규화해 사용자 전체 개념을 대상으로 최대 3개를 반환한다. 이름 일치만으로 의미가 같다고 단정하지 않는다. AI 검토 입력에도 추출 후보의 이름·별칭 검색 결과를 추가해 초기 200개 밖의 관련 개념을 포함한다.
- AI 추천은 자동 선택하지 않는다. 각 후보에서 **기존 개념에 연결** 또는 **별개 개념으로 추가**를 선택한 뒤 최종 등록한다. 다른 대상은 기존 검색/선택 메뉴로 직접 선택할 수 있다.
- 기존 개념 연결을 선택하면 해당 개념의 정의·범위를 표시한다. 별개 개념으로 되돌리면 연결 전 작성 내용을 복원한다. 선택과 원본 초안은 노트 버전별 브라우저 임시 저장에 포함한다. 새 개념의 이름·정의·범위·별칭을 변경하면 등록 방식을 다시 확인한다.
- 추천이 없다는 것은 중복이 없다는 뜻이 아니다. 수동 검색은 이름/별칭 기준이며, AI 의미 비교도 입력된 개념 풀 안에서 수행한다. 검색 실패는 후보 없음과 구분한다.

## 기존 학습과의 연결

- 기존 `knowledge_entries`는 보존한다. 시작 시 등록된 단원/기초 과정만 출처와 영구 개념으로 이관한다. 출처 단위 매핑을 저장하므로 재시작해도 중복 생성되지 않는다.
- 기초 과정에는 과정 제목에 대응하는 개념을, 자료 과정에는 기존 개념 목록에 대응하는 개념을 만든다. 기존 이름들을 의미가 같다는 이유로 자동 통합하지 않는다.
- 이관한 개념은 `provisional`이다. 노트 등록 시 기존 ID에 연결할 수 있고, 명시적으로 정의를 보완하면 같은 ID를 유지하며 `confirmed`가 된다. `confirmed`는 사용자 검토를 뜻하며 객관적 숙달을 뜻하지 않는다.
- 현재 지도는 영구 개념 ID를 사용한다. 과거 AI 요약과 날짜별 `learning_records`는 그대로 보존하며 날짜별 보기에서 확인할 수 있다. 기존 단원의 통과 문제는 공통 개념에 별도의 풀이 근거로 연결된다.
- 기존 자료가 삭제되면 출처 근거는 비활성화한다. 과거 등록 스냅샷과 당시의 기록은 유지한다.

## 변경·보관·복습

- 노트 수정 시 이전 출처는 `stale`. 현재 주장/관계 및 새 복습 연결의 유효 근거로 사용하지 않는다. 지도에 남은 이전 노트 노드는 재검토 상태를 표시한다.
- 새 노트 버전을 등록할 때 기존 개념 ID를 다시 선택할 수 있다. 동일 주장/관계에는 새 출처 근거를 붙인다.
- 노트 보관은 논리적 삭제다. 복원하면 새 리비전이 생성되며, 그래프에 재등록해야 한다.
- 복습은 현재 노트와 승인된 공통 개념·한 단계 관계로 연결된 출처를 최대 5개 사용한다. 미해결 질문 또는 반박된 관계를 긍정적 연결의 근거로 쓰지 않는다. 본문 발췌는 첫 노트 12,000자, 연결 노트 각 8,000자다.
- AI 출처 ID는 응답 스키마의 enum으로 제한하고 서버에서도 확인한다. 화면 문장에는 노트 이름을 사용하고 인용 버튼은 실제 출처 ID로 연결한다.
- AI 장애/재시작 시 제출된 설명은 유지한다. 재시도는 같은 답변을 두 번 관찰로 기록하지 않는다.

## 내보내기와 한계

- ZIP: `note.md`, `metadata.json`(노트 버전·개념·별칭·주장·출처·근거 ID), `images/*.webp`. Markdown 이미지는 상대 경로로 바꾼다.
- 이미지는 PNG/JPEG/WebP, 장당 4 MB·2천만 픽셀 이하. 서버에서 EXIF 방향을 적용하고 메타데이터를 제거한 WebP로 저장한다(최대 2560px). 계정당 이미지 100 MB. 원본 해상도의 이미지 보관소로 사용하는 기능은 아니다.
- 이미지 OCR/시각 분석, 옵시디언 폴더 가져오기, 그래프 개념 일괄 병합, 임베딩 검색, PDF/동영상 원문 수집은 구현 범위에 포함하지 않는다.
- 직접 검색은 이름·정의·별칭으로 최대 200개를 반환한다. 비교 카드의 이름·별칭 조회는 사용자 전체 개념을 검사한다. AI는 초기 200개와 추출 후보별 추가 조회 결과를 비교하므로, 이름·별칭이 전혀 다른 관련 개념은 입력 풀에서 누락될 수 있다.
- 근거 위치와 그래프 구조 검사는 사실성 평가를 대신하지 않는다. 별도 AI 내용 검토도 오류를 놓치거나 잘못 지적할 수 있으므로 제안은 사용자가 확인한다. AI 복습 피드백은 참고용으로 표시한다.
